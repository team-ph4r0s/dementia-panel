# История изменений

Формат версий `vX.Y.Z` и правила выбора номера — в [docs/releases.md](docs/releases.md). Каждая версия публикуется на GitHub
как релиз; текст релиза берётся из соответствующего раздела этого файла.

## v0.2.28 — 2026-11-09

### Новое
- **«Напрямую, мимо VPN»** («Подписки»): выберите страны (например, Россия), свои домены и сети — сайты и приложения оттуда открываются без VPN, даже когда он включён. В приложениях на ядре mihomo (FlClash, Clash Verge, Mihomo Party) правила `DOMAIN-SUFFIX` / `GEOIP` / `IP-CIDR` добавляются в подписку для AWG и VLESS. Для AmneziaWG (Incy, `.conf`) есть опция: из `AllowedIPs` вычитаются IP-сети выбранных стран и свои сети (домены в WireGuard невозможны); списки сетей панель скачивает сама и обновляет по кнопке. В v2rayN, Happ и Hiddify правила по ссылке не передаются.

## v0.2.27 — 2026-11-07

### Новое
- **Страница подписки переработана**: кнопки «Добавить в приложение» открывают Incy, FlClash, Clash Verge Rev, Hiddify, v2rayNG, Happ, Streisand, Shadowrocket, sing-box и NekoBox и добавляют подписку сами (приложения подбираются по протоколам подписки, платформа пользователя — первой). Поле со ссылкой и кнопка «Копировать», полоса расхода трафика, оформление Topology; страница стала легче (без сетки-фона и лишних блоков).

## v0.2.26 — 2026-11-07

### Исправления
- **Смена IP панели:** если Cloudflare не ответил при переводе A-записи домена, адрес раньше считался применённым — баннер пропадал, кнопка «Обновить везде» блокировалась, а домен оставался на старом IP. Теперь адрес остаётся неприменённым (красный баннер, кнопка доступна, автообновление повторяет попытку после временной ошибки).
- Самоподписанный сертификат по IP перевыпускается на новый адрес вместе с переводом остального; раньше редирект HTTP → HTTPS вёл на старый IP.
- У установки без домена смена IP теперь замечается (панель запоминает первый замеченный адрес), а публичный адрес, заданный IP, считается известным адресом.
- Резервный домен: при временном сбое связи с Cloudflare запись старого IP больше не теряется из учёта, а шаг отчёта не показывает зелёное, пока записи не совпали с нужными. Два одновременных применения не путают «прежний» адрес.

## v0.2.21 — 2026-11-06

Мосты — основной путь для пользователей страны.

### Новое
- **Режим привязки «Основной» (`main`) — по умолчанию для новых привязок.** Пользователь страны моста получает ноду через мост первой записью, а прямую — запасной следом («· напрямую»): если мост лёг, можно переключиться в приложении.
- **Панель через мост.** Кнопка на карточке моста: мост пересылает порт панели на сервер панели (TCP как есть, TLS и сертификат — панели). Интерфейс и подписки доступны через мост, даже если IP панели или Cloudflare в стране режут.
- **Резервный домен подписок** («Мосты → Резервный домен подписок»): одно имя без оранжевого облака, у которого панель держит A-записи — IP работающих мостов с «Панелью через мост» и (по выбору) прямой IP панели. Имя добавляется в сертификат панели (Let's Encrypt через Cloudflare), ссылки подписок выдаются с ним; приложение при недоступности одного адреса пробует следующий. Мост ушёл в offline — его адрес убирается из DNS автоматически. Прежние ссылки продолжают работать.

### Исправления
- Карта топологии показывала привязки «Всегда через мост» как ожидающие — теперь они (и «Основной») отображаются работающими.

## v0.2.20 — 2026-11-06

### Новое
- **Транспорт XHTTP для VLESS.** В «Параметрах Reality» можно выбрать TCP или XHTTP, путь и режим (`auto`, `packet-up`, `stream-up`, `stream-one`). XHTTP передаёт данные HTTP-запросами и лучше переживает «заморозку» длинных сессий. Ссылки, mihomo и подписки — с параметрами XHTTP; flow Vision с XHTTP не выдаётся (без VLESS Encryption Xray его не поддерживает). «Сгенерировать новые» транспорт не меняет.
- **Вход через CDN Cloudflare для нод VLESS.** Если IP ноды заблокирован, клиенты могут подключаться к адресам Cloudflare: панель выпускает сертификат Let's Encrypt (DNS-01 сохранённым токеном), создаёт A-запись с оранжевым облаком и поднимает на ноде второй вход VLESS + XHTTP + TLS на HTTPS-порту Cloudflare. В подписках появляется запись «· CDN»; можно указать «чистый» IP Cloudflare для подключения. Сертификат продлевается автоматически, при ошибке настройки всё откатывается. Reality-вход не меняется.
- Существующим VLESS-нодам выдан случайный путь XHTTP (миграция v16). В инспекторе ноды — транспорт и вход через CDN.

### Исправления
- Удаление VLESS-ноды удаляло контейнер `dementia-xray`, даже если он не принадлежит панели (без метки `dementia.env`). Теперь чужой контейнер не трогается.

### Тесты
- `real-docker-vless.test.ts`: установка Xray на Docker-узле, подключение настоящим клиентом Xray по TCP и XHTTP, блокировка частных сетей по IP и по имени, учёт трафика, отказ непринятого конфига, вход через CDN по TLS, удаление.

## v0.2.19 — 2026-11-06

### Безопасность
- Нода VLESS блокировала клиентам доступ в частные сети (127.0.0.0/8, 10.0.0.0/8…) только при обращении по IP: домен, указывающий на 127.0.0.1 (например, `localtest.me`), правило обходил, и клиент VPN мог достучаться до API Xray и служб самого хоста ноды. Маршрутизация Xray теперь `IPIfNonMatch` — домены резолвятся и сверяются с тем же правилом. Применяется при следующей синхронизации ноды (добавление клиента, «Синхронизировать»).

### Исправления
- Синхронизация и применение параметров VLESS-ноды проверяют новый конфиг `xray run -test` образом работающего контейнера до замены: если Xray его не принял, прежний конфиг и контейнер не трогаются, в карточке ноды — ошибка. Раньше конфиг перезаписывался сразу и нода могла уйти в перезапуски.

## v0.2.18 — 2026-11-06

### Исправления
- Установка VLESS-ноды падала на проверке конфигурации («Failed to get format of /etc/xray/config.json.new»): Xray определяет формат по расширению файла, временный конфиг теперь `config.new.json`. Конфиг панели проверен на образе `ghcr.io/xtls/xray-core` 26.10.31, включая подключение клиента по выданной ссылке и учёт трафика.

## v0.2.17 — 2026-11-06

Второй протокол: VLESS + Reality (Xray-core).

### Новое
- При добавлении сервера можно выбрать протокол **VLESS Reality** (TCP, по умолчанию 443). Панель ставит контейнер Xray `dementia-xray` по SSH, генерирует ключи и параметры Reality; конфиг ноды собирается из базы, как у AmneziaWG.
- Окно «Параметры Reality»: SNI, адрес маскировки, shortId, flow и отпечаток TLS; применение с откатом при ошибке. Метка протокола AWG/VLESS у нод.
- Клиенты VLESS получают ссылку `vless://` и QR-код; UUID клиента не отдаётся в API и гостю. Трафик считается по статистике Xray.
- Подписки: ссылки `vless://` в общем списке, прокси VLESS в mihomo, записи VLESS в JSON и новый формат `?format=v2ray` (определяется и по User-Agent v2rayN/v2rayNG/Hiddify/Streisand/Happ/NekoBox).
- Мосты пересылают VLESS-ноды по TCP.

### Ограничения
- VLESS-ноды пока нельзя передавать партнёрам; нет импорта Xray из AmneziaVPN, автообновления образа Xray и проверки из стран.
- Добавление и удаление клиента VLESS перезапускает контейнер Xray (соединения переподключаются за секунды).

## v0.2.16 — 2026-11-05

Исправления по итогам аудита безопасности и надёжности.

### Безопасность
- WebSocket панели проверяет сессию перед каждой командой; выход, отзыв сессии, смена пароля или логина сразу закрывают её сокеты.
- Ограничение подбора пароля при входе стало строже: успешный гостевой вход больше не обнуляет счётчик неудач адреса; слишком длинные логин и пароль отклоняются сразу, а память ограничителей не растёт без предела.
- Вывод команд на нодах ограничен 16 МБ: неисправная или взломанная нода больше не может исчерпать память панели.
- Обновлены зависимости с известными уязвимостями (`node-forge`, `follow-redirects`, тестовый `vitest`). В CI добавлены `npm audit`, права токена «только чтение» и закрепление actions по SHA.
- Служба `dementia.service` получила дополнительные ограничения systemd (`LockPersonality`, `RestrictRealtime`).

### Исправления
- Обновление установок прежнего имени (Demension, `/opt/demension-panel`) теперь действительно скачивает новый код.
- Две правки порта или параметров ноды подряд при неудачном применении больше не оставляют в БД и подписках значение, которого нет на ноде.
- Проверка «контейнер панели» требует точного монтирования `/opt/amnezia/awg`: установка не удалит чужой контейнер Amnezia из-за похожего пути.
- Сканирование ноды, завершившееся во время переноса панели, не записывает результат в старую панель.
- Отклонённое изменение сетевых настроек (DNS, MTU, адрес) больше не сохраняется частично.
- Кириллица в журналах установки и выводе нод больше не искажается на границе блоков данных.
- `reset-admin.js` с `PANEL_RESET_2FA=1` (или `--reset-2fa`) отключает 2FA, если утеряны аутентификатор и коды восстановления; без флага предупреждает, что 2FA включена.
- `install.sh` хранит только 5 последних резервных копий БД, а при обрыве во время создания администратора всё равно показывает сгенерированный пароль.
- Интерфейс: кнопки-действия и размер текста приведены к теме Topology, устранены предупреждения линтера; форма сервера не сбрасывает ввод при фоновом обновлении списка.
- Тест дополнительного входа Cloudflare проходит и в Windows.

## v0.2.13 — 2026-11-04

### Новое
- **Отдельный домен панели через Cloudflare.** В разделе «Безопасность» можно указать домен и API токен: панель создаст или обновит A-запись с оранжевым облаком, при необходимости выпустит сертификат DNS-01 и сохранит новый публичный адрес для подписок. Токен для сертификатов можно использовать повторно. По умолчанию открывается дополнительный HTTPS-вход на 443; если порт занят, доступны другие HTTPS-порты Cloudflare. Основной порт панели и контейнеры AmneziaWG не меняются.
- Домен, используемый известной VPN-нодой или мостом, проксировать нельзя; посторонние A/AAAA/CNAME-записи не перезаписываются. При сбое настройки восстанавливаются прежние HTTPS и адрес панели, выполняется откат подтверждённых изменений DNS. Отключение проксирования оставляет DNS-запись, HTTPS и текущий адрес для прямого доступа.
- Заголовок IP клиента учитывается только от настоящих адресов Cloudflare; произвольным `X-Forwarded-For` и `X-Forwarded-Proto` панель доверять не начинает. API и подписки получают запрет кэширования для CDN.

### Исправления
- **Сохранённый токен Cloudflare теперь явно виден в настройках HTTPS.** Секрет не возвращается в браузер; пустое поле позволяет повторно проверить и использовать сохранённый токен. Повторный выпуск сертификата больше не выключает уже включённое оранжевое облако.

Для подключения домен должен обслуживаться Cloudflare. Выберите там **SSL/TLS → Full (strict)** и откройте выбранный **TCP-порт** в фаерволе VPS/хостинга. Для VPN используйте прямой IP или отдельный DNS-домен без проксирования. Не включайте кэширование и CAPTCHA для API и подписок.

## v0.2.12 — 2026-11-04

### Новое
- **Обновления контейнеров AmneziaWG из панели.** Раз в сутки панель скачивает `latest` на работающие управляемые ноды и сравнивает ID образа с работающим контейнером. В разделе «Серверы» появились проверка образов, кнопка «Обновить все» и автообновление в выбранный час UTC (по умолчанию выключено). Ноды обновляются по одной; во время замены VPN кратковременно прерывается.
- **Сохранение клиентов и откат.** Обновление не меняет БД клиентов, ключи, подписки или конфиги. Перед остановкой сверяются работающие и сохранённые пиры; после запуска — ключи, IP и keepalive каждого пира. При ошибке новый контейнер удаляется, прежний возвращается и проверяется. Несохранённые ручные изменения блокируют обновление до остановки. Контейнеры приложения Amnezia и ноды партнёров автоматически не обновляются.
- Доступность обновлений и результаты записываются в журнал событий; Telegram использует существующие настройки уведомлений. После неудачи автоматическая попытка повторяется не чаще раза в сутки.

## v0.2.0 — 2026-10-26

Надёжная проверка доступности нод и мосты в странах пользователей.

### Проверка доступности нод
- **Ping больше не используется**: провайдеры умеют подделывать ответы ICMP, и нода выглядела доступной, когда до неё ничего не доходило.
- При включённой проверке панель сама ставит на каждую ноду **заглушку** — отдельный контейнер `dementia-probe` со страницей «Coming soon»
  на случайном свободном порту, который отвечает и по TCP, и по UDP. Контейнер AmneziaWG она не трогает.
- Узлы check-host.net в выбранных странах обращаются к заглушке по HTTP и UDP, а панель **по журналу на самой ноде** проверяет, что запросы
  действительно дошли. Нода считается доступной из страны, если до неё дошёл UDP (как трафик AmneziaWG). Ответ, подделанный по дороге,
  не засчитывается и помечается знаком ⚑.
- Ноды партнёров (без SSH) проверяются по заданному TCP-порту, как раньше; для своих нод этот порт — запасной.

### Мосты
- Новая вкладка **«Мосты»**: промежуточный сервер (ретранслятор) в стране пользователей добавляется так же, как нода — адрес и SSH-доступ, остальное
  панель настроит сама. Docker на мосту не нужен: он пересылает трафик AmneziaWG на зарубежные ноды (iptables), шифрование остаётся
  сквозным, ключей пользователей на мосту нет.
- К мосту привязываются ноды, у каждой — режим: **авто** (мост выдаётся, когда нода недоступна из страны моста), **всегда** (для сбоев маршрута
  у отдельных операторов связи, которые проверки не видят) или **не использовать**.
- У пользователя появилась **страна**. Если нода недоступна из его страны, подписка сама выдаёт адрес моста этой страны (в названии — 🌉 и флаг);
  ключи и параметры остаются прежними, меняется только адрес. Работает во всех форматах подписки.
- «Нужен мост» решается по двум сигналам: две проверки подряд показали, что из страны нода недоступна, **или** у нескольких клиентов этой страны
  одновременно оборвались подключения к ноде, а у остальных нет (это видит и сбои, не заметные проверке из дата-центров). Обратно на прямой адрес — после трёх
  удачных проверок и не раньше чем через 12 часов, чтобы адрес не менялся при каждом обновлении подписки.
- Панель регулярно проверяет мост: правила на месте, а пересылка работает от начала до конца (ответ заглушки ноды через мост). Неработающий мост
  в подписку не попадает.

### После обновления
- Если проверка доступности была включена, при первой проверке на ноды поставится заглушка (нужен доступ к Docker Hub с ноды).

### Возможности
- **Перенос панели на другой сервер.** На прежней панели («Безопасность → Перенос панели на другой сервер») выдаётся код переноса; на новом
  сервере тот же `install.sh` в режиме «Перенос» забирает всё: логин и пароль администратора, ноды (с SSH-доступами), клиентов,
  пользователей и подписки, партнёров, токен Cloudflare, настройки и ключ шифрования. Данные передаются зашифрованными кодом переноса
  (в том числе по обычному HTTP). Пока архив передан, прежняя панель не принимает изменения, после переноса — замораживается, а её ссылки
  подписок перенаправляются на новый адрес. Автоматический режим: `MIGRATE_FROM`, `MIGRATION_CODE`, `PANEL_CERT_MODE`… Подробнее — `docs/migration.md`.
- **Сертификат при переносе.** Установщик спрашивает способ в терминале: Let's Encrypt через Cloudflare API (сохранённый в прежней панели
  токен используется сам; домен можно указать новый), Let's Encrypt по HTTP-проверке, самоподписанный на IP, свой сертификат (путь к
  файлам на новом сервере), а также оставить сертификат прежней панели или продолжить без HTTPS.
- **Смена логина администратора** («Учётная запись» в шапке, рядом со сменой пароля) — по текущему паролю; остальные сессии завершаются.
- **Доступность нод из стран.** В разделе «Серверы» выберите до 8 стран — панель проверяет через check-host.net (ping или TCP-порт ноды),
  достучались ли до ноды оттуда. Результаты видны на карточках нод и в подписке: к названию ноды добавляется «🇷🇺✅ 🇰🇿❌», к описанию —
  пояснение. Выключено по умолчанию (адреса нод уходят на check-host.net); показывает сетевую доступность адреса ноды, но не работу протокола. Подробнее — `docs/probes.md`.
- Предупреждение в разделе «Безопасность»: подписки по `https://` с самоподписанным сертификатом на IP работать не будут.

### Безопасность и надёжность
- Неверные пароли при смене логина/пароля и выдаче кода переноса ограничены (5 за 15 минут на администратора).
- **Исправлено:** обновление панели с включённым HTTPS через `install.sh` завершалось ошибкой «Панель не отвечает» (проверка запуска по HTTP
  получала 403), хотя панель работала. Теперь `/api/health` доступен и по HTTP.
- Сертификаты без поля CN (современный Let's Encrypt) получают имя из SAN.

### После обновления
- Миграция БД (v8) применяется сама. Проверка из стран и перенос ничего не меняют, пока вы их не используете.

## v0.1.0 — 2026-10-24

Первый релиз: всё, что было сделано до введения версий.

### Возможности
- Развёртывание AmneziaWG в Docker на нодах по SSH, синхронизация клиентов без разрыва соединений, применение параметров
  обфускации, мониторинг нод и учёт трафика.
- Параметры AmneziaWG 3.x для новых серверов, переход 1.x → 3.x по кнопке.
- Подключение уже установленных контейнеров AmneziaWG (в т.ч. приложения AmneziaVPN) и импорт по ключам «Полный доступ».
- Пользователи с автообновляемыми подписками (Incy, mihomo, JSON), лимиты трафика и срока, оформление подписки.
- Партнёрский доступ к нодам между панелями.
- HTTPS (Let's Encrypt, Cloudflare, свои сертификаты) на одном порту с HTTP для подписок, fail2ban.
- Отображение версии панели, последней версии на GitHub и версий ПО AmneziaWG на нодах.

### Безопасность и надёжность
- Шифрование SSH-доступов и токенов в БД, хэши токенов сессий и партнёров, CSP, проверка данных от панелей партнёров.
- Случайные логин и пароль администратора при установке; установка не удаляет чужой контейнер AmneziaWG.
- Если ноде не удалось применить новый порт или параметры, они возвращаются к прежним — подписки не раздают то, чего нет
  на ноде.
- `install.sh`: обновление скачивается до остановки службы, добавленные вручную переменные `.env` сохраняются.
