# Домен панели через Cloudflare

«Безопасность → Домен панели · Cloudflare»: отдельный домен панели, API токен, IPv4 сервера (пусто — определить автоматически), email для выпуска сертификата и HTTPS-порт.

## Подключение

1. Добавьте свою DNS-зону в Cloudflare и включите её обслуживание там (правильные NS).
2. Создайте API токен с **Zone → Zone → Read** и **Zone → DNS → Edit** на эту зону. Если токен уже сохранён для сертификатов, поле можно оставить пустым.
3. В Cloudflare выберите **SSL/TLS → Full (strict)**. Flexible и Off не подходят: панель принимает от Cloudflare настоящий TLS. Режим всей зоны и настройки остальных сайтов панель не меняет.
4. Выберите отдельный домен, например `panel.example.com`, и порт. По умолчанию **443**; альтернативы — **2053, 2083, 2087, 2096, 8443**. Нестандартный порт будет частью URL. Текущий порт панели (например, 3001) продолжит работать. Если выбранный TCP-порт занят или недоступен службе, DNS не меняется. Откройте его в фаерволе сервера и хостинга; панель не меняет правила фаервола.
5. Подтвердите настройку. Если действующий сертификат не покрывает домен, панель выпустит Let's Encrypt через DNS-01 (email нужен только при выпуске). Временная TXT-запись не требует открытия 80 порта. Затем создаётся A-запись `proxied: true`, `ttl: 1` и обновляется `public_url`. Откройте новый адрес в отдельной вкладке; автоматического перехода нет, чтобы можно было проверить Cloudflare и доступность порта.

Адреса уже выданных подписок не переписываются в устройствах пользователей: они хранят полный URL. При смене домена или порта передайте пользователям новые ссылки. HTTP-ссылки `/sub` на прежнем основном порту остаются доступны; смена сертификата может потребовать новый адрес для старых HTTPS-ссылок с другим именем.

## VPN на том же сервере

Оранжевое облако проксирует HTTP(S)/WebSocket, а не обычный UDP AmneziaWG. Панель и контейнер могут работать на одной машине:

- `panel.example.com` → IP VPS, **Proxied** — сайт, API, подписки;
- VPN `Endpoint` → **IP VPS** или `vpn.example.com` с **DNS only**.

Ни контейнеры, ни клиенты, ни ключи, ни VPN-порты не меняются. Имя, которое совпадает с `host` известной ноды или моста, отклоняется до обращения к DNS. При добавлении/изменении локальной ноды запрещается указывать активный проксируемый домен панели. Проверка не обнаруживает произвольные внешние CNAME-цепочки: выбирайте действительно отдельное имя.

Для нового имени допускаются отсутствие адресной записи или одна A-запись на тот же IPv4. Другой IP, CNAME, AAAA или несколько адресных записей — отказ без перезаписи. Для уже сохранённой записи панели допустима явная смена IPv4 (например, после переноса), если её ID, зона, имя и прежний IP всё ещё совпадают с сохранёнными данными. Остальные записи зоны не удаляются и не редактируются.

Cloudflare не гарантирует доступность при блокировке самого домена или адресов Cloudflare. IP VPS останется в прямых VPN-конфигурациях; это не скрытие IP VPN-сервера.

## HTTPS, безопасность и откат

`CloudflarePanelService.configure` и все изменения HTTPS из API/автопродление используют общую очередь `SslService.exclusive`.
Перед изменением TLS/DNS резервируется порт, в памяти сохраняются прежние сертификат/ключ и настройки. Новый токен фиксируется только после успешного DNS. При ошибке прежние HTTPS, токен и публичный адрес восстанавливаются; для подтверждённой созданной DNS-записи выполняется удаление, для изменённой — возврат прежних proxied/ttl/IP. При невозможности отката DNS API явно требует ручной проверки. Таймаут внешнего API может означать неопределённый результат DNS-записи: проверьте её в Cloudflare перед повтором.

Дополнительный listener использует тот же HTTPS-сервер, API и WSS, что и основной порт. Состояние восстанавливается при перезапуске; ошибка порта отображается в карточке. При отключении оранжевого облака A-запись переводится в DNS only, но HTTPS/listener и URL сохраняются для прямого доступа. Если запись вне панели изменила имя/IP/тип, отключение отказывается её редактировать. При смене домена прежняя DNS-запись автоматически не удаляется.

`cf_token` хранится через `encryptSecret`. Статусы отдают только `cfTokenSaved`/`token_saved`; значение токена никогда не выдаётся. Старые сертификаты и токены не требуют миграции. Выпуск/продление сертификата сохраняют уже установленный `proxied: true`.

`CF-Connecting-IP` используется только при включённой функции и только если **реальный socket peer** входит в официальные сети Cloudflare. Диапазоны зафиксированы в `middleware/cloudflare.ts` по `https://www.cloudflare.com/ips-v4` и `/ips-v6`. `TRUST_PROXY=true` не включается; заголовок `X-Forwarded-Proto` не заменяет настоящий TLS, поэтому партнёрский API продолжает требовать HTTPS. При изменениях сетей Cloudflare нужно обновить список.

Для `/api` и `/sub` выставляются `Cache-Control`, `CDN-Cache-Control`, `Cloudflare-CDN-Cache-Control` с `no-store`. Не создавайте в Cloudflare правила, принудительно кэширующие их или требующие CAPTCHA/браузерную проверку: приложения подписок не проходят эти проверки. WSS также должен пропускаться без CAPTCHA.

## Перенос и резервные копии

Настройки `cf_panel_*`, `cf_token` и сертификаты входят в обычный снимок панели. DNS сам по себе при импорте архива не меняется. После переноса укажите новый IPv4 в карточке и повторите настройку; если сертификат не перенесён, потребуется выпустить его заново. При смене IP вне панели проверка отключения защиты может потребовать ручной проверки записи.

API: `GET /api/security/cloudflare` — статус; `POST` — `{domain, token?, origin_ip?, email?, port?}`; `DELETE` — отключение проксирования. Только администратор; записи блокируются при переносе панели обычным middleware. DNS-проверки/продление сертификата остаются на существующем расписании; фоновой смены DNS нет.
