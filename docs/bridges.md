# Мосты в странах пользователей

Мост — промежуточный сервер (ретранслятор) в стране пользователей, через который они подключаются к удалённой ноде, когда прямой
маршрут до неё недоступен или нестабилен (сетевой адрес ноды или UDP-порт не отвечает из этой страны). Подписка пользователя, у которого
задана страна, сама выдаёт адрес моста этой страны для тех нод, где это нужно.

Код — `server/src/services/bridge.service.ts`, `routes/bridges.ts`, скрипт установки `server/src/scripts/deploy-bridge.sh`, подмена
адреса — `routes/subscription.ts`; интерфейс — `BridgesView.tsx`, `BridgeModal.tsx` (вкладка «Мосты»), страна пользователя —
`AddSubscriberModal.tsx`.

## Как устроен мост

Мост **пересылает пакеты** правилами iptables (DNAT + MASQUERADE), а не расшифровывает трафик:

- UDP `мост:listen_port` → `нода:awg_port` — трафик AmneziaWG; шифрование остаётся сквозным, ключей пользователей на мосту нет,
  конфигурация клиента отличается от прямой только строкой `Endpoint`;
- TCP `мост:listen_port` → `нода:stub_port` — на заглушку проверки доступности ноды ([probes.md](probes.md)); через неё панель
  проверяет пересылку целиком (см. «Сквозная проверка»). Если заглушки на ноде нет, TCP не пересылается.
- нода **VLESS** (`protocol = 'vless'`, [vless.md](vless.md)) пересылается одним правилом TCP `мост:listen_port` → `нода:awg_port`;
  панель проверяет сквозной TLS-путь по сертификату сайта маскировки.

Для DNAT Docker на мосту не нужен. Установка (`deploy-bridge.sh`, по SSH через stdin, как установка ноды): ставит iptables при необходимости,
включает `net.ipv4.ip_forward`, записывает `/etc/dementia-bridge/rules.sh` и службу `dementia-bridge.service`, которая применяет
правила после перезагрузки (без systemd правила восстановит панель при очередном опросе).

`rules.sh` **генерируется целиком из БД** (`buildBridgeRules`, как конфиг ноды): цепочки панели `DEMENTIA-BRIDGE` (nat PREROUTING),
`DEMENTIA-BRIDGE-POST` (nat POSTROUTING) и `DEMENTIA-BRIDGE-FWD` (filter FORWARD) очищаются и заполняются заново. Переходы в них
ставятся **первыми** в цепочках (прежние удаляются): политика DROP в FORWARD от Docker или ufw иначе отбрасывала бы пересылаемый
трафик. DNAT срабатывает только для пакетов на адреса самого моста (`-m addrtype --dst-type LOCAL`) — исходящий трафик контейнеров
на мосту не перехватывается. Адрес ноды подставляется только после проверки (`isValidHost`) и в кавычках `shellQuote`; домен
разрешается на мосту (`getent ahostsv4`) при каждом применении. Ноды с IPv6-адресом не поддерживаются.

**Порт на мосту** для новой ноды — её порт AmneziaWG, если он не занят другой нодой этого моста и не совпадает с SSH-портом, иначе
случайный 20000–60999. У уже привязанной ноды порт не меняется: иначе пользователи с подпиской, полученной через мост, потеряют VPN.

## Каскад XHTTP

В карточке установленного моста у сохранённой привязки к локальной ноде нажмите «Каскад XHTTP». Оставьте автоподбор порта или укажите свой свободный TCP-порт на ноде.
Для этой привязки трафик пойдёт по схеме **клиент → прежний порт моста → VLESS XHTTP Reality → локальный порт VPN на ноде**.
Поддерживаются UDP AmneziaWG и TCP VLESS. Клиентские ключи и ссылки менять не нужно. Режимы выдачи моста в подписке задаются отдельно.

- На обоих Linux-хостах нужен запущенный Docker, на мосту также `conntrack` и `iproute2`. При включении каскада панель устанавливает
  недостающие зависимости на мосту через пакетный менеджер; Docker — из репозитория Docker CE, а при его недоступности (`download.docker.com` закрыт) из репозиториев дистрибутива. Причина сбоя показывается в ошибке моста. Обычный DNAT работает без этих зависимостей. Хосты должны быть разными, партнёрские ноды
  не поддерживаются. Откройте TCP-порт каскада на ноде для адреса моста и прежний порт на мосту для клиентов. При включённой
  заглушке AWG панель использует также TCP на том же порту моста. VPN-порт и порт заглушки должны быть доступны на `127.0.0.1` ноды.
  Reality на ноде нужен доступ к выбранному сайту маскировки по TCP 443.
  Для AmneziaWG с опубликованным Docker-портом нужен `userland-proxy`. Если UDP-порт недоступен на loopback ноды,
  панель отклоняет включение каскада.
- **Чек-лист.** 1) Docker запущен на мосту и ноде. 2) Оставьте автоподбор порта (или укажите свободный TCP-порт сами): ufw, firewalld и iptables на ноде панель
  откроет сама, внешний фаервол хостинга откройте вручную. 3) Клиентский порт моста (прежний) открыт на мосту. 4) Поле «Сайт маскировки Reality» можно оставить пустым: это **чужой
  популярный сайт** (TLS 1.3, HTTP/2, открывается с ноды по TCP 443), под который Reality маскирует трафик, — не домен панели и не
  ваш домен. Сменить его можно, только отключив каскад.
- На каждом хосте запускается отдельный контейнер Xray для этой привязки. На ноде Xray принимает только созданные панелью
  учётные данные и передаёт трафик только на `127.0.0.1` с портом VPN или TCP-заглушки. Секрет хранится в БД зашифрованным
  и передаётся в конфиг через stdin по SSH. Образ каскада закреплён по digest для проверки точных правил выхода Xray.
  Обычные контейнеры VPN сохраняют свою конфигурацию.
- Для новой привязки панель выбирает сайт маскировки из списка Reality. Имя хранится в зашифрованных реквизитах привязки
  и используется на обеих сторонах. У ранее включённых каскадов сохраняется прежнее имя `dl.google.com`.
- Образ Xray загружается отдельным шагом до замены контейнеров и правил. Для скачивания на каждом хосте отведено 18 минут.
  UDP AmneziaWG идёт внутри TCP, поэтому при потерях могут расти задержки и снижаться скорость.
- При смене транспорта панель очищает записи conntrack только для порта привязки на локальных IPv4-адресах моста.
  Открытые соединения могут переподключиться. При ошибке развёртывания панель пытается вернуть прежнюю пересылку.
  При неполной очистке параметры остаются доступны для повторного применения или отключения.
- Панель проверяет, что контейнер на мосту работает и TCP-порт каскада доступен с моста. Отдельно проверяется сквозной путь
  внутри XHTTP: для AWG с заглушкой по её метке, для VLESS по сертификату сайта маскировки. Эти проверки не подтверждают
  пользовательское VPN-соединение.
- Недоступная нода одной привязки не блокирует мост: правила и остальные привязки применяются, а каскад этой привязки остаётся
  неприменённым (`cascade_pending`, в подписку не выдаётся), причина — в ошибке моста. Повтор — раз в интервал проверки. Сбой при
  настройке самой привязки, как и прежде, отменяет изменение.
- «Отключить каскад» снимает оба контейнера и возвращает DNAT. Перед сменой TCP-порта, отвязкой ноды, удалением или сменой хоста
  моста или ноды отключите каскад. Для снятия уже применённого каскада нужен SSH-доступ к обеим сторонам.

**Автоподбор порта.** По умолчанию порт выбирает нода: панель берёт кандидатов (8443, 2053, 2083, 2087, 2096, 8843, 9443 и случайные из 20000–49999),
убирает порты, которые знает как занятые (SSH, VPN, заглушка, CDN и запасные порты всех нод панели с тем же адресом, каскады других мостов), а скрипт
на ноде берёт первый, который не слушают ни по TCP, ни по UDP (`ss -Hlntu`, без `ss` — `/proc/net`; пустой список слушающих портов считается ошибкой).
Порт, заданный вручную, проверяется так же и отклоняется (409), если занят. При каждом применении каскада порт открывается на ноде: в активном **ufw** или **firewalld**, а если их нет — правилом `ACCEPT` в начале `INPUT`
**iptables**, но только когда цепочка что-то отбрасывает (политика или правило `DROP`/`REJECT`). Для iptables порт записывается в
`/etc/dementia-cascade/<контейнер>/port`, а службу `dementia-cascade-ports.service` (она читает эти файлы) панель включает, чтобы правило пережило
перезагрузку; при отключении каскада правило и файл удаляются. Только IPv4. Внешний фаервол хостинга панель открыть не может — откройте порт в нём сами,
иначе применение остановится на проверке доступности порта с моста.

Запрос `PUT /api/bridges/:id/links/:serverId/cascade` с телом `{ "port": "auto" }` включает каскад с подбором порта, `{ "port": 8443 }` — с заданным, с `{ "port": null }` отключает.
В списке привязок виден `cascade_port`. Секрет и ключи API не выдаёт.

## Привязка и режимы

У каждой пары мост × нода (`bridge_links`) свой режим:

| Режим | Что выдаёт подписка пользователям страны моста |
|---|---|
| `main` (по умолчанию) | **Мост — основной путь**: первой записью нода через мост, следом запасная прямая (`<имя> · напрямую`) — пользователь переключится в приложении, если мост лёг |
| `auto` | Адрес моста, пока для этой ноды и страны действует состояние «нужен мост» (`bridge_state.active`) |
| `always` | Всегда адрес моста — для сбоев маршрута, которые проверки не видят (например, только у части операторов связи) |
| `off` | Прямой адрес; правила пересылки при этом остаются |

Мост выдаётся, только если он `online` и сквозная проверка пересылки не провалилась (`check_ok` не `0`); иначе пользователь получает
прямой адрес (в режиме `main` — одной записью). Если у ноды несколько
подходящих мостов в стране, берётся мост с меньшим id. В названии ноды появляется пометка `· 🌉 🇷🇺`. Подмена адреса работает во
всех форматах подписки (Incy, JSON, mihomo); выданные вручную файлы `.conf` и QR-коды не меняются.

## Панель через мост

Кнопка «Панель через мост» на карточке (`bridges.panel_forward`, миграция v17) добавляет в правила моста ещё одну пересылку:
TCP `мост:<порт панели>` → `<IPv4 панели>:<порт панели>` (`buildBridgeRules(links, panel)`). Пакеты идут как есть: TLS завершается на
панели, сертификат её собственный, мост ничего не расшифровывает. Через мост доступны интерфейс панели и подписки
(`https://<адрес моста>:<порт>/…`, для проверки имени — резервный домен, ниже).

- Порт на мосту — тот же, что у панели (`PORT`, по умолчанию 3001; HTTP и HTTPS на одном порту, инвариант 20). Он не должен совпадать
  с SSH-портом моста и с портами нод этого моста; новым нодам этот порт не выделяется.
- IPv4 панели — `panel_origin_ip` (явный → адрес из настройки домена Cloudflare → определённый автоматически), сохраняется при включении.
- Включение/выключение сразу применяет правила; если мост их не принял — флаг возвращается (502).
- Панель видит подключения через мост с адреса моста (MASQUERADE): ограничение входа по IP считает их как один адрес.

## Резервный домен подписок: одна ссылка — несколько путей

Ссылка подписки — это один URL. С доменом под оранжевым облаком Cloudflare DNS отдаёт только адреса Cloudflare: подмешать к ним IP моста
нельзя. Поэтому резервный путь — **отдельное имя без проксирования** (DNS only), например `sub.example.com`
(`FailoverService`, «Мосты → Резервный домен подписок», `POST /api/bridges/failover`):

- панель держит у имени A-записи (`proxied: false`, TTL 60): IP **работающих** мостов с «Панелью через мост» (только IPv4-адреса мостов)
  и, по выбору (`include_panel`, по умолчанию да), прямой IP панели. `BridgeService.checkAll` после каждого опроса сверяет набор
  (`FailoverService.reconcile`): мост ушёл в `offline` — его запись удаляется, вернулся — добавляется. Без изменений Cloudflare не
  трогается; пустой набор не публикуется (лучше прежние адреса, чем пустой DNS);
- имя добавляется в сертификат панели (`ssl_alt_names`, Let's Encrypt DNS-01 тем же токеном; продление его сохраняет). Нужен
  сертификат через Cloudflare или его отсутствие — загруженный вручную/HTTP-01 сертификат на домене вне аккаунта не расширить;
- ссылки подписок в интерфейсе строятся от `https://<имя>:<порт панели>` (`/api/settings` → `subscription_url`). Прежние ссылки
  (через Cloudflare или IP) продолжают работать — передайте пользователям новые, когда включите;
- приложения (Go/OkHttp/URLSession) при недоступности одного адреса пробуют следующий из ответа DNS — так одна ссылка работает и через
  мосты, и напрямую. Заблокированный «заморозкой» адрес отнимает время до таймаута, поэтому держите в DNS только нужные адреса;
- только свои записи: имя должно быть свободно (или с нашими A-записями), проксируемое имя отклоняется; изменения DNS/TLS — через
  `SslService.exclusive`; при ошибке настройки записи, сертификат и настройки откатываются. Выключение удаляет наши записи и убирает имя
  из списка сертификата (уйдёт при продлении).

<a id="check"></a>

**Проверка.** «Проверить путь к панели» на карточке моста (`POST /api/bridges/:id/panel-check`, `FailoverService.checkBridge`) идёт из панели
по шагам: пересылка включена → правила применены → TCP до `мост:<порт панели>` → TLS с именем резервного домена (или домена сертификата) и
проверкой, что сертификат выписан на это имя → `GET /api/health` через мост. Так видно, где рвётся: закрытый порт на мосту или на сервере
панели (мост пересылает **основной порт панели** `PORT`, а не 443 Cloudflare), сертификат без резервного имени, нет ответа. Доступность моста
из страны пользователя отсюда не видна. «Проверить DNS» (`POST /api/bridges/failover/check-dns`) сравнивает ответ 1.1.1.1/8.8.8.8 с
опубликованными адресами.

**Частая ошибка:** включить «Панель через мост» и ждать, что старые подписки пойдут через мост. Ссылка в приложении — это URL; через мост
идут только ссылки с резервным доменом. Подписку в приложении нужно добавить заново по новой ссылке. Ссылка `https://<IP моста>:порт/…`
не работает: сертификат выписан на имя, а не на IP. Приложение переходит на следующий адрес, только если **подключение не установилось**;
«заморозка» уже открытого соединения (троттлинг) переключения не вызывает — такие адреса не держите в DNS (флажок «Прямой IP панели»).

**Что надёжнее, если в стране режут Cloudflare.** Адреса Cloudflare нельзя заблокировать без огромного побочного ущерба, но их можно
замедлить (в РФ с июня 2025 у многих провайдеров обрыв после ~16 КБ — интерфейс панели не загрузится, маленькая подписка иногда
проходит). Мост внутри страны с «белым» адресом обычного хостинга этим ограничениям не подвержен, но его IP могут заблокировать
точечно — поэтому мостов лучше несколько, и резервный домен держит их все. Связка «ссылка через резервный домен (мосты + прямой IP) +
старая ссылка через Cloudflare» покрывает оба случая.

## Кому нужен мост: решение с гистерезисом

`BridgeService.evaluate` пересчитывает `bridge_state` для каждой пары нода × страна, у которой есть мост в режиме `auto`.

**Проверка из страны** ([probes.md](probes.md)) — проблема, если до ноды дошли меньше половины узлов страны (`ok_nodes * 2 < total_nodes`).
Серии считаются только после проверок (`evaluate(true)` из `ProbeService.afterRun`), каждая проверка — один шаг:

- мост включается после **2** проблемных проверок подряд (`FAIL_STREAK_TO_ACTIVATE`);
- выключается после **3** проверок подряд без проблем (`OK_STREAK_TO_RELEASE`) и не раньше чем через **12 часов** после включения
  (`BRIDGE_HOLD_MS`) — пользователи не должны метаться между адресами при каждом обновлении подписки;
- если нода недоступна самой панели (`status != 'online'`), состояние не меняется: мост тут не поможет.

**Сигнал от клиентов** (`passiveSuspect`) — проверка видит только сетевую доступность из дата-центров, а клиенты — реальную работу протокола в своих сетях. Сигнал есть, если:

- у клиентов ноды из страны (страна подписчика) за последние 6 часов были рукопожатия, и минимум **3** из них последний раз
  связались с нодой в пределах **10 минут** друг от друга (не меньше 60% клиентов страны, активных в последний час перед обрывом);
- с тех пор прошло не меньше **15 минут** тишины;
- у клиентов других стран (или без страны) рукопожатие было за последние 5 минут — нода жива.

Одновременность отличает сбой на маршруте от того, что пользователи отключались по одному (например, вечером). Сигнал от клиентов включает
мост сразу (в нём уже есть 15 минут ожидания); пересчёт идёт каждую минуту (`probeLoop`). Выключение — как выше; если страна не
проверяется из стран, мост выключается по истечении 12 часов, когда сигнал от клиентов пропал. После перехода на мост рукопожатия клиентов
возобновляются (уже через мост), поэтому сигнал гаснет сам.

Без страны у пользователя мост ему не выдаётся. Сигнал от клиентов и проверку можно сочетать: мост включается по любому из них.

## Фоновые проверки

- `BridgeService.checkAll` (из `statsLoop`, каждые 30 с): если правила в БД изменились (порт или адрес ноды, заглушка, удалённая нода —
  сравнивается SHA-256 с `bridges.rules_hash`) или стоит `needs_apply`, правила применяются заново; раз в две минуты мост проверяется по
  SSH — правила на месте, переход в FORWARD первый. Правила пропали или сдвинуты — `needs_apply`. Три неудачи SSH подряд — `offline`.
  Мосты в статусе `error` (неудачная установка, смена ключа SSH-хоста) автоматически не трогаются.
- **Сквозная проверка** `checkLinks` (после каждой проверки из стран): панель открывает `http://мост:listen_port/<случайный путь>`; мост
  пересылает TCP на заглушку ноды, и ответ должен содержать её метку `stub_token`. Ответа нет или метка чужая — `check_ok = 0`, мост
  для этой ноды не выдаётся, пока следующая проверка не пройдёт.
- **VLESS:** статистический цикл проверяет каждую применённую привязку примерно раз в две минуты, в том числе при выключенной проверке
  из стран. Панель открывает TLS к порту моста с SNI ноды и проверяет доверенную цепочку сертификата и имя. Предел проверки — 8 секунд
  и 128 КиБ входящих данных. Записываются результат и время проверки. Ошибка скрывает маршрут до следующей удачной проверки.
  Это проверка пути до сайта маскировки из сети панели. Успех не подтверждает авторизацию VPN и не отличает другой путь к тому же сайту.
- Все операции с одним мостом идут через ту же очередь `runExclusive`, что и ноды, по ключу `bridge:<id>`. На время переноса панели
  циклы на паузе.

## API `/api/bridges` (администратор)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/` | Мосты с `links: [{server_id, server_name, server_host, awg_port, listen_port, mode, check_ok, checked_at, active, reason, changed_at}]` |
| POST | `/` | `{name, host, ssh_port?, ssh_user?, ssh_password \| ssh_key, country, links?, install?}` — добавить и сразу установить (`install: false` — только добавить); ответ `{success, error?, log, bridge}` |
| PUT | `/:id` | Имя, адрес, SSH-доступ, страна (`reset_host_key: true` — сбросить ключ хоста), `panel_forward: bool` (+ `origin_ip`) — панель через мост |
| POST | `/:id/panel-check` | Путь «мост → панель» по шагам `{ok, host, port, name, steps: [{ok, title, detail}]}` |
| POST | `/failover/check-dns` | `{domain, resolved, published, missing, extra, error}` — ответ публичного DNS против опубликованного |
| GET/POST/DELETE | `/failover` | Резервный домен подписок: состояние; `{domain, include_panel?, origin_ip?, token?, email?}`; выключить |
| PUT | `/:id/links` | `{links: [{server_id, mode}]}` (`mode`: `main` по умолчанию, `auto`, `always`, `off`) — ноды моста; правила применяются сразу, при ошибке привязки возвращаются к прежним (502) |
| POST | `/:id/install` | Установка (повторная) с журналом |
| POST | `/:id/apply` | Применить правила |
| POST | `/:id/test-ssh` | Проверка SSH |
| DELETE | `/:id` | `?teardown=1` — убрать цепочки и автозапуск с сервера, `&force=1` — удалить из панели даже при ошибке |

SSH-пароль и ключ моста хранятся зашифрованными и в ответах не отдаются (`has_ssh_password`, `has_ssh_key`). Страна пользователя —
поле `country` в `POST/PUT /api/subscribers` (двухбуквенный код, пусто — не задана).

## Данные
