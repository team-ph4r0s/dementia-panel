# Провайдеры: кабинеты, платежи и напоминания

Вкладка «Провайдеры» хранит для **панели, каждой ноды и каждого моста** (ноды партнёров не показываются) данные, нужные,
чтобы вовремя платить за серверы: ссылку на личный кабинет провайдера, логин, пароль, сумму платежа в месяц и дату платежа.
За несколько дней до платежа и в его день панель присылает напоминание в Telegram администратору.

## Данные

Таблица `provider_accounts` (миграция v21, [database.md](database.md)): одна строка на сервер.

| Поле | Смысл |
|---|---|
| `target_type`, `target_id` | `panel` (id `0`), `node` (`servers.id`) или `bridge` (`bridges.id`) |
| `url` | ссылка на кабинет, только `http://`/`https://` (иначе в интерфейсе мог бы появиться `javascript:`) |
| `login`, `password` | `password` шифруется `encryptSecret` — как SSH-доступы и токен Cloudflare |
| `amount`, `currency` | сумма в месяц и валюта (`RUB`, `USD`, `EUR`) |
| `pay_day`, `pay_month` | день 1–31 и необязательный месяц |

Если после сохранения все поля пусты, строка удаляется.

### Дата платежа

- Без месяца платёж **ежемесячный**: достаточно числа.
- С месяцем платёж **ежегодный** (например, 15/03).
- Число, которого нет в месяце (31 февраля), переносится на последний день месяца.
- Ближайшая дата считается от сегодняшнего дня в UTC (`nextDueDate`, `utils/providers.ts`); платёж «сегодня» ещё считается ближайшим.

## Секреты

- Список (`GET /api/providers`) отдаёт только `password_saved`. Пароль возвращает отдельный `GET /api/providers/:type/:id/password` — по кнопке с глазом.
- `PUT` без поля `password` оставляет пароль как был, пустая строка стирает.
- Вкладки нет в белом списке гостя (`GUEST_READABLE`), поэтому гость получает 403; тест `guest-access.test.ts` это проверяет.
- Логин и пароль не попадают ни в сообщение Telegram, ни в журнал событий.

## Напоминания

`ProviderService.tick` вызывается из цикла в `index.ts` раз в 15 минут.

1. Ничего не делает, если напоминания выключены, идёт перенос панели (`isBackgroundPaused()`), или ещё не наступил настроенный час (UTC).
2. Для каждого сервера с датой считает, сколько дней осталось до ближайшего платежа. Если это число есть в `remind_days` (по умолчанию `[1, 0]` — накануне и в день платежа) и напоминание на эту пару `(дата платежа, дней до платежа)` ещё не уходило — отправляет его.
3. Отправка идёт через `TelegramService.notify` (бот и ID чата настраиваются в «Безопасность → Уведомления в Telegram»). Отметка в `provider_reminders` ставится **только после успешной отправки**: при ошибке Telegram повтор будет при следующем запуске.
4. Смена данных сервера сбрасывает его отметки; записи старше 60 дней и строки удалённых серверов чистятся.

Настройки хранятся в `settings`: `providers_remind_enabled` (по умолчанию включено), `providers_remind_days` (JSON-массив, 0–30), `providers_remind_hour` (UTC, по умолчанию 6 ≈ 09:00 по Москве).
Если Telegram не настроен, вкладка показывает предупреждение (`telegram_ready: false`), а напоминания молча не уходят.
